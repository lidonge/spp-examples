# 第22章 生成链路物理资源与运行配置

> © 2026 S++ project contributors. All rights reserved. [Book copyright](https://github.com/lidonge/spp-examples/blob/main/book/COPYRIGHT.md).

声明式业务模型最终需要变成可执行代码、接口、仓储与资源访问。生成链路承担这项转换，同时检查模型和实现契约是否匹配。阅读生成结果，是理解声明实际作用的重要方法。

## 从模型到运行产物

编译器解析业务模型、服务调用、扮演关系与事务边界，再结合 APP 和 PHY 生成 Java 模型、服务、映射、OpenAPI、DDL 和运行目录等产物。具体输出依模块与配置而定。

这条生成链路也承接第三篇第12章介绍的 AI 协作方式：AI 主要维护 SPP、APP 和 PHY 源码，大量模型、映射、接口和框架接入代码由工具按规则生成。减少 AI 自由输出的实现代码，也减少需要由 AI 逐处保持一致的关系。

业务变更的人工审查因此可以集中在 SPP 的角色、规则与场景，并通过业务结果验证它们。大量生成代码的重复结构由工具链维护；工具链或适配能力改变时，再针对相应生成行为检查实现。这样的分工减少逐次审查全部混合代码的负担，也使人更容易核对 AI 输出是否符合业务需求。

业务源码保留在源目录，生成 Java 位于 target。修改生成文件只能影响一次构建产物，下一次生成可能覆盖它；业务规则应在 SPP 或相应源配置中维护。

## 生成时与启动时的检查

生成时可以发现未定义事实、歧义绑定、非法服务调用、不支持事务传播或矛盾资源配置。启动时还要根据实际覆盖参数检查环境、资源身份、提供方契约与就绪状态。

静态检查不能证明远程服务此刻能够完成所有交易，启动检查也不能代替并发与故障验证。不同层次的检查对应不同证据。

## 构建与本地演示

以下命令在仓库根目录执行，要求仓库说明中的 JDK 17、Maven 与依赖条件：

```bash
mvn -pl :petstore-demo -am package -DskipTests -Dspp.environment=develop
SPP_PETSTORE_JDBC_URL='jdbc:h2:file:/tmp/spp-book-petstore' \
  ./demos/petstore/run-demo.sh web
```

演示网页默认使用 8086 端口。这里指定独立实验数据库；重复使用同一路径会保留先前数据。完整环境变量和分进程命令见附录 E。

## 数值与资源

PHY 选择数字表示和存储容量，APP 组织技术映射。业务表达中的舍入仍由 SPP 明确，物理转换无法精确兑现时应失败。

相同的业务场景在 develop 与 testing 下可以使用不同部署关系和提交计划。比较运行结果时，应同时查看所选环境、生成目录与实际启动参数，避免用一套产物证明另一套配置。

## 验证声明的兑现

构建成功说明源码和生成链路达到相应检查层级，实际业务仍需要调用场景并核对结果。下一篇沿 Petstore 展开，从业务需求到资金与库存流转，观察角色与服务架构如何形成一个完整系统。
