# 量子调用范围

> © 2026 S++ project contributors. All rights reserved. [Book copyright](https://github.com/lidonge/spp-examples/blob/main/book/COPYRIGHT.md).

量子服务描述数值变化；调用者决定本次成交值的上下限。业务不手写范围校验，也不增加技术型min/max参数。

```spp
quantum update transfer(Buyer buyer, Merchant merchant, PaymentAgreement agreement) {
    buyer.wallet -= agreement.paymentAmount;
    merchant.cash += agreement.paymentAmount;
}
// 置于场景的显式transaction中：
transfer(buyer, merchant, agreement) bounds {
    buyer.wallet: [0, null];
    merchant.cash: [0, null];
};
```

## 语义

- 区间是闭区间，上下限为数字表达式或null，在调用前求值。null表示对应方向不校验，两侧null表示不校验范围。
- 负下限可表达透支；角色中的授信等业务事实可用于数字边界表达式。集合目标的同一表达式边界应用于本次集合各成员。
- 上下限随调用传入量子服务的成交实现，由实现保证本次成交满足范围；越界不成交，并触发绑定事务撤销。禁止调用者在成交完成后补做范围检查。下限大于上限也是拒绝，不执行更新。
- 范围不改变量子守恒、记录与事务资源要求。旧调用省略bounds兼容为没有新增范围限制；不是停用量子一致性。
- 账户状态等非量子资格仍由场景调用check。普通check、guard及breakTransction的既有约定不变，SPP没有异常捕获语法。

## 编译与表示

bounds只允许显式事务中的量子update（包括APP绑定量子提供方的调用），目标必须是实际传入参与者的量子属性；重复路径、非量子属性、非法维度、非数字边界拒绝。显式别名及默认参与者名均可使用。集合范围逐成员传递给提供方，禁止用总量替代单成员范围。

PHY决定数字表示，边界表达式使用相应NumericAdapter。业务语义不要求所有数字类型转换成BigDecimal；具体成交实现须提供与其表示匹配的边界能力和编码。当前守恒账簿使用十进制Number编码，非Number自定义量子类型仍需补充账簿编码，不能只靠数学适配器宣称已支持。舍入如属业务须显式表达。

当前通用执行入口支持AT/QUANTUM物理保障；其他PHY策略须接入其一致执行与撤销能力，不能把Saga补偿当作确定回滚。业务语法不选择这些实现模式。

## 当前证据

Petstore的资金和库存调用展示此语法，普通账户下限0由调用场景选择；量子服务体没有固定范围check。已生成并编译，未运行负/null/动态边界、越界回滚或并发回归。旧服务内check暂保留兼容，不是新服务默认写法。

量子属性业务上统一归逻辑量子域，真实一致性机制由APP配置、PHY资源实现；不是强制独立物理服务。事务内读取和混合参与者保护见[事务读取规则](spp-transaction-reads.md)。

## 不同实现的责任

SPP声明本次业务范围；生成器通过量子调用元数据传递，不增加普通业务参数。APP选定量子成交实现，PHY接入存储资源。同一语法可对应不同控制方式，通用层不规定统一检查算法。

- JDBC版：提供方在量子资源事务内同步并锁定成交基线。已有属性使用UPDATE，范围直接成为该语句的WHERE条件；首次建立值使用带范围条件的INSERT SELECT。条件不满足、影响行数为零，则拒绝成交，同连接内的量子流水及其他写入一并撤销。文本数值存储不强制转为固定精度DECIMAL；已有DECIMAL(38,12)存储容量不足时拒绝，不能静默舍入后写入。
- 内存账簿版：现有实现只记录变化，尚未提供权威当前值及原子边界成交机制，因此不声明支持调用边界。不能仅检测传入的afterValue就声称保障并发成交范围。
- 专用量子服务：提交记录可携带minimum/maximum，由支持该协议的客户端和提供方保证成交。客户端默认不声明支持；现有HTTP与logical/commands协议尚未接入动态调用边界，不能当作已完成。普通远程原子服务调用也尚未透传此元数据，有实际范围时明确拒绝。
- TCC等版本：须在各自成交协议中接入范围控制，不能用调用后的检查代替。当前未接入的执行实现拒绝有实际上下限的调用；两侧null不添加限制。

本地APP跨域投影同时传递边界，范围不会在消费域和提供域重复检查。生成的getQuantumBounds元数据覆盖提供方的成交基线读取、变化记录与提交链路，不只包裹业务方法体。Java运行时中的能力声明属于框架接口，不是SPP业务参与者或Java业务适配器。

## 守恒分组与全部量子更新

显式 APP `quantum resource(ledger, Account.balance, Cash.balance, Income.balance) settle;` 的属性列表定义需要求和为零的守恒组。服务内对其他量子属性的更新仍必须生成：例如同次成交中欠息减少、额度释放，保留原来的持久化、调用 bounds、成交值回填和系统反交易，不能因未列入资金组而丢弃更新。

未显式选择守恒属性时，继续按被更新的量子属性推导守恒组。显式选择时，编译器保留完整更新集合并校验它们属于同一量子存储协调范围；资金组仍要求至少两个不同属性及增加/减少方向。声明的未变化资金成员也保留在完整守恒快照中。

内置 JDBC 协议使用保留组名 `$state` 记录未列入守恒组的量子变化；它不参与资金求和，但不能绕过属性的上下限，也必须随整笔量子事务提交、回填和反向恢复。APP 的资源标识不能写这个内部名字。此协议扩展的验收范围为内置 JDBC 实现；外部量子服务与 TCC 协议需要单独验证其兼容性。
