# 事务外普通事实的默认乐观保障

> © 2026 S++ project contributors. All rights reserved. [Book copyright](https://github.com/lidonge/spp-examples/blob/main/book/COPYRIGHT.md).

普通参与者在事务外查询、校验和计算，事务内更新时，APP 的 `persist(update, ...)` 缺省使用查询基线做原子条件提交。SPP 无需定义技术版本，也无需在事务内重新查询或重复业务校验。只有本事务实际更新的普通事实进入比较条件；买家准入和商品资格等只读事实不因此成为全局锁或提交条件。

## 通用 JDBC 实现

普通快照一行保存 `payload_json` 与不可重复的 `revision_token`，一次 SELECT 取得两者。查询原地补全入口参与者时同步转移修订基线；集合成员补全和同 JVM 跨域模型投影也传递基线。同一入口角色代表多个域的事实时，分别保存各对象类型和身份的修订基线。

默认更新生成数据库条件写入：`UPDATE ... SET payload_json=?, revision_token=? WHERE object_type=? AND object_id=? AND revision_token=?`。影响行数不是一行即报告 `PERSISTENCE_VERSION_CONFLICT`，绑定事务撤销。新标记使用 UUID，避免删除、重建对象造成旧基线重新有效。成功更新推进该对象的基线；源事务失败恢复参与者基线。没有可靠读取基线的更新明确拒绝，不能在保存前读取最新版本再覆盖。原生 APP 表兜底查询目前不提供修订基线，不能用于默认乐观更新。

仓储快照是普通事实的权威来源；查询快照后不再使用另一次原生表读取覆盖业务事实。原生 APP 表索引用于定位身份，更新投影与快照条件更新共同提交。外部写入者必须经过仓储或同时维护快照与标记，仅改原生表不能获得本机制保障。

`ObjectRepository.updateFromRead` 对未实现条件更新的适配器明确拒绝。旧 `compareVersion/advanceVersion` 语法保留兼容；Petstore 已改用缺省保护，移除手写平台 version 列。JDBC 平台版本兼容路径也要求可靠快照修订基线。

## 普通与量子事实分离

APP 的 quantumStore 属性清单确定量子事实。普通快照及普通表投影排除这些属性，包括关联角色中的量子属性副本。角色首次开立时在共同资源连接中初始化量子值，查询时由量子值存储补全。量子成交只改变量子权威值，不刷新角色普通修订标记；量子服务仍在成交内部同步权威基线，并由具体实现执行调用处 bounds。

本轮补全的是选择 JDBC 量子账簿时的仓储事实组合。该组合要求同一资源连接共同提交；其他量子提供方须实现自己的事实加载、开立和提交协议，当前不支持时明确拒绝配置。量子域的业务语义不限定为 JDBC，也不承诺跨库共同提交。

## 请求协调与多个事务

JDBC 场景防重先用短事务登记 RUNNING 请求，业务执行不在隐含 JDBC 事务中，结束后用短事务记录 COMPLETED 输出。普通原子调用的兼容入口保留原行为，场景使用独立协调入口。

已测得完全回滚且没有任何独立源事务提交的失败，可以释放请求登记，允许调用方再次尝试。已有阶段提交、提交结果不确定或没有可靠撤销证据时，登记为 RECOVERY_REQUIRED；进程中断遗留 RUNNING 也不自动重放。当前未实现自动恢复协调器：需要查询业务凭证确认事实，再由技术运维恢复请求记录。这是多个独立提交阶段的实际限制，不能通过重新执行整场景掩盖。

## 数据兼容及验证范围

新建快照表包含 revision_token；旧数据库需要离线迁移或使用独立演示数据库。迁移时必须先停止写入，为原普通快照分配标记，并核对、初始化缺失的量子权威值后移除副本；已有量子账簿值优先，不能用旧快照覆盖成交值。本轮未自动迁移、修改现有数据库或重启网页。

仅生成、编译及静态检查。测试源码覆盖过期基线拒绝、缺失基线拒绝、量子成交不推进普通版本、顺序阶段保留及嵌套共同撤销；未执行并发、失败、恢复或重启测试。
