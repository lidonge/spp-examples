# 第六篇 完整实践 Petstore

> © 2026 S++ project contributors. All rights reserved. [Book copyright](https://github.com/lidonge/spp-examples/blob/main/book/COPYRIGHT.md).

前五篇已经建立业务模型、服务协作、语言表达、一致性与技术分离的原则。本篇沿一位买家的完整办理过程，把这些原则落实到 Petstore 的模型、场景、APP 与 PHY。先建立零事实，充值与入库，再报价、下单、付款、发货，最后观察后续办理和失败处置。

业务线使用一组可逐步核对的假设金额与数量；源码片段链接到实际文件。已有实现与验证范围据实说明，缓存、按需数据和完整安全治理等扩展能力以改造方案呈现。性能实验和详细论证仍放在附录。

## 先看与 Java 的代码量对照

这套 Petstore 覆盖四个业务域、34 个场景，包括会员、商品、购物车、订单、付款、交付、退货与预约。以本书使用的源码生成 Java，得到以下统计：

|内容|文件数|代码行数|
|---|---:|---:|
|SPP 业务模型、服务与场景|63|999|
|业务枚举|2|18|
|APP 与 PHY 技术及物理配置|8|331|
|人工维护的 S++ 源码合计|73|1,348|
|工具生成的 Java|962|100,151|

行数不计空行和注释，包含单独的括号行。这里约一千行的业务表达，加上三百多行配置，生成了约十万行 Java，涵盖模型、请求与响应、接口、服务实现和技术接入。业务人员主要阅读并维护 SPP，模型展开、调用与保存等代码由工具确定性生成。

采用 Spring Boot＋MyBatis＋Lombok 开发同样的商店，可以作一个粗略工程估算：

|Java 开发范围|预计需要人工维护的代码与配置|
|---|---:|
|34 个场景的常规单体实现，使用本地数据库事务|约 6,000～10,000 行|
|再覆盖本案例的多域调用、守恒交易、持久幂等与失败恢复职责|约 10,000～20,000 行|

这里把 Java、SQL／Mapper 和必要配置一起计入，与 S++ 的业务及配置合计比较；不计框架依赖、测试、网页和自动展开的访问方法。Lombok、框架和通用组件已经承担一部分重复代码，估算没有假定 Java 开发者需要逐行重写生成结果。

由此可以建立一个大致印象：本案例约 1,350 行 S++ 业务与配置，对应常见 Java 框架方案约一万到两万行需要维护的项目源码。Java 范围是按职责拆分的估算，尚未通过独立实现测量；十万行则是实际生成量，两者不能混用。统计与估算依据见 [附录 F7](../附录/f-sources-and-evidence.md#f7-petstore-代码量统计)。
